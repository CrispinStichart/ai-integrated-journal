# ADR-0006: First usable release boundary

- Status: Accepted
- Date: 2026-08-15
- Deciders: Project maintainers
- Requirements: ARCH-005, DATA-001–013, TIME-001–003, STATE-006–007, AC-001, AC-003

## Context

The implementation plan calls the Phase 2 milestone the first usable release and requires it to remain useful without an AI provider or worker. Later phases add recoverable audio, transcript lineage, processors, search, and portability. The boundary must prevent foundation work from expanding indefinitely while still producing a safe private journal.

## Decision

The first usable release is the **secure source-only text journal** completed by implementation-plan tasks 7–20. It includes:

- the pinned monorepo/toolchain, local PostgreSQL infrastructure, typed configuration, domain kernel, shared API contracts, database foundation, operational API/worker shells, PWA shell, and authentication vertical slice;
- one private owner with secure session, recovery, CSRF, and logout/cache-clearing behavior;
- stable Journal Days and typed contributions for past, present, and future dates;
- append-only text revisions, visible contribution boundaries/provenance, optimistic conflicts, audited day reassignment, soft deletion, restoration, and capture/journal timezone preservation;
- versioned `/api/v1` journal contracts with idempotent mutations, ETags, deterministic pagination, RFC 9457 errors, and operational health behavior;
- a mobile-first accessible calendar/day UI;
- an IndexedDB text outbox and explicitly bounded, user-scoped cached reads, with ordered retry, deduplication, conflict handling, logout clearing, and offline shell;
- complete operation when no AI provider is configured and when the worker is stopped or failing;
- local-only operation under the deployment constraints already documented.

The release does **not** include browser audio capture/upload/playback, STT or transcript layers, configurable or built-in processors, nudges generated by processors, AI providers, search, embeddings, exports, backup/restore tooling, permanent-deletion sweeping, or a supported phone-over-LAN deployment. Interfaces and shells may exist, but they are not user-facing completed capabilities.

Phase 2 verifies the structural portion of AC-001—that one day presents multiple independently identifiable contributions—using typed/source fixtures. The recording-specific end-to-end portion of AC-001 is not claimed complete until tasks 21–25. AC-003 is verified in Phase 2 by showing that text capture/view/edit remains independent of worker/provider availability, and is re-run with recording and processing failures at later milestones.

## Release gates

All repository quality gates applicable to the implemented scope must pass. In addition:

1. A clean local install can bootstrap the owner, sign in, create/edit/move/delete/restore text, restart, and recover the same history.
2. Offline creation survives reload and synchronizes once without duplication after reconnect.
3. Cached reads are bounded and user-scoped; logout removes them.
4. Stopping the worker and leaving all provider configuration absent does not impair source workflows.
5. No generated value is the sole record of user content.
6. Firefox desktop automation covers the critical path. Physical Firefox Android capture validation remains a Phase 0 task 4 / later PWA milestone gate because the first release has no microphone workflow.

## Consequences

- The earliest releasable product is useful before the highest-risk audio and AI integrations exist.
- The milestone does not claim full product-specification conformance.
- AC-001 and AC-003 retain staged traceability entries until their complete cross-phase scenarios pass.

## Rejected alternatives

- Including audio in the first boundary contradicts the dependency-ordered Phase 2 milestone and delays validation of the durable journal core.
- Omitting authentication or offline durability would produce a demo rather than the specified private, recoverable journal.
- Including processor output would violate the goal of proving source usefulness independently of AI.
